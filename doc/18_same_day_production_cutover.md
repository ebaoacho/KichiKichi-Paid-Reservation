# 当日予約 本番切り替え手順書

## 目的

既存の当日予約プラグインをすぐに停止せず、新しい当日予約フォームへ安全に切り替えるための手順を固定する。

この手順では、旧当日予約導線と新当日予約導線を比較し、限定URLで確認してから本番ページのショートコードを差し替える。問題があった場合は、旧ショートコードへ戻して旧プラグインの受付を継続する。

## 切り替え前提

- Step 1 から Step 8 までの確認スクリプトが `Result: PASSED` であること。
- WordPress 管理画面で `KichiKichi Paid Reservation` が有効であること。
- 旧当日予約プラグインは、切り替え完了まで停止しないこと。
- 新しい当日予約フォーム用の確認ページを作成できること。公開状態は、非公開またはURLを知っている担当者だけが開く限定URLにする。
- 新しい当日予約確認・キャンセル用の確認ページを作成できること。公開状態は、非公開またはURLを知っている担当者だけが開く限定URLにする。
- 管理者が席数設定タブで `Bar` / `Table` の席数を確認できること。
- Table 席を受付する日は、管理者が Table の席数を明示的に 1 以上へ設定すること。

## 新旧導線の比較表

| 観点 | 旧当日予約プラグイン | 新当日予約導線 |
| --- | --- | --- |
| フォーム | 旧プラグインのフォーム | `[kkpay_same_day_reservation_form]` |
| 確認・キャンセル | 旧プラグインの確認ページ | `[kkpay_same_day_confirmation]` |
| 保存先 | `kichikichi_reservation_customer` | `kkpay_reservations` |
| 席数設定 | `kichikichi_reservation_limits` | `kkpay_slot_capacities` |
| 席種 | `Table` / `Bar` | `Table` / `Bar` |
| 受付開始 | 旧プラグインの開始操作 | 管理画面の当日予約開始 API |
| 受付終了 | 開始から3時間、または満席 | 開始から3時間、または満席 |
| キャンセル | 旧レコードを削除 | `status = cancelled` / `cancelled_at` 更新 |
| 管理一覧 | 旧当日予約一覧 | 管理画面の当日予約タブ |
| プレミアム予約との競合 | 旧当日予約内だけで判定 | 共通残席ロックで判定 |
| Table 初期値 | 旧プラグイン設定値 | 未設定時は 0 |

新導線では、Table 席数が未設定の枠は `0` として扱われる。そのため、Table 席を受付する日は、切り替え前に席数設定タブで Table を 1 以上に設定しないと、お客様はその日の Table 枠を予約できない。

## 限定URL確認手順

1. WordPress に当日予約フォーム確認用ページを作成する。公開状態は、非公開またはURLを知っている担当者だけが開く限定URLにする。
2. 本文に `[kkpay_same_day_reservation_form]` を配置する。
3. WordPress に確認・キャンセル確認用ページを作成する。公開状態は、非公開またはURLを知っている担当者だけが開く限定URLにする。
4. 本文に `[kkpay_same_day_confirmation]` を配置する。
5. 管理画面の席数設定タブで、確認対象日の `Bar` と `Table` の席数を設定する。
6. Table を受付しない日は `Table = 0` のままにする。
7. 管理画面 → 当日予約タブを開き、受付開始ボタンを押して当日予約の受付を開始する。
8. 限定URLでフォームを開き、言語、名前、メール、人数、席種、時間枠を入力して予約する。
9. 管理画面の当日予約タブに予約が表示されることを確認する。
10. 確認・キャンセルページで同じメールアドレスを入力し、予約内容が表示されることを確認する。
11. キャンセルを実行し、管理画面で `cancelled` として確認できることを確認する。

## 旧導線との同等性確認

次の項目を旧導線と新導線で比較する。

- 受付開始前は予約できないこと。
- 新システムの管理画面「受付開始」ボタンで、新フォームが受付中になること。
- 旧プラグインの「受付開始」ボタンで、旧フォームが受付中になること。新旧の受付開始操作は独立している。
- 受付開始後、3時間以内だけ予約できること。
- 09:30 から 12:00 未満は `slot_1` / `slot_2` が対象になること。
- 13:30 から 16:00 未満は `slot_3` / `slot_4` / `slot_5` / `slot_6` が対象になること。
- 満席枠が選択肢に出ないこと。
- `Table` / `Bar` の選択が残席計算に反映されること。
- 同一メール・同日・同一時間枠の重複予約が作成されないこと。
- 予約確認がメールアドレスでできること。
- キャンセル後に同じ予約を再キャンセルできないこと。
- 管理画面で時間枠ごとの合計人数が確認できること。

## 本番切り替え手順

切り替えは JST 0:00 以降、開店前に実施する。旧プラグインの日次削除は UTC 15:00（JST 0:00）に走るため、その後であれば旧システムに当日分の未キャンセル予約が残っていない状態で切り替えやすい。

1. 旧当日予約ページの本文とショートコードを控える。
2. 旧当日予約確認・キャンセルページの本文とショートコードを控える。
3. 本番ページの本文を `[kkpay_same_day_reservation_form]` に差し替える。
4. 確認・キャンセルページの本文を `[kkpay_same_day_confirmation]` に差し替える。
5. 管理画面の席数設定タブで、当日と翌営業日の `Bar` / `Table` 席数を確認する。
6. Table 席を受付する日だけ `Table` を 1 以上にする。
7. 管理画面の当日予約タブを開き、今日の日付が表示されることを確認する。
8. 本番ページを開き、フォームが表示されることを確認する。
9. 確認・キャンセルページを開き、メール入力フォームが表示されることを確認する。
10. 旧当日予約プラグインはこの時点では停止しない。

## 切り戻し手順

新導線で問題が出た場合は、旧導線へ戻す。

1. 本番当日予約ページの本文を、控えておいた旧ショートコードへ戻す。
2. 確認・キャンセルページの本文を、控えておいた旧ショートコードへ戻す。
3. 旧当日予約プラグインが有効であることを確認する。
4. 旧当日予約フォームを開き、受付状態と時間枠が表示されることを確認する。
5. 新導線で作成済みの予約がある場合は、管理画面の当日予約タブで控える。
6. 必要に応じて、店舗運用上の台帳へ新導線で作成された予約を転記する。
7. 旧プラグインの残席計算には `kkpay_reservations` に作成された新導線予約が反映されないため、当日の残り枠は店舗側で手動管理する。
8. 原因調査が終わるまで、旧プラグインを停止しない。

## 旧プラグイン停止前チェックリスト

- [ ] 新フォームで予約作成できる。
- [ ] 新確認ページで予約確認できる。
- [ ] 新確認ページでキャンセルできる。
- [ ] 管理画面の当日予約タブで今日の予約が確認できる。
- [ ] 管理画面の席数設定タブで `Bar` / `Table` の席数を保存できる。
- [ ] Table 席を使う日の Table 席数が 1 以上に設定されている。
- [ ] Table 席を使わない日の Table 席数が 0 になっている。
- [ ] プレミアム予約が `Bar` 残席を消費することを確認した。
- [ ] キャンセル後に残席が戻ることを確認した。
- [ ] 旧当日予約ページのショートコード控えが残っている。
- [ ] 切り戻し担当者と連絡先が決まっている。
- [ ] 本番切り替え直後の監視担当者が決まっている。

## 切り替え後の監視

切り替え当日は、少なくとも次を確認する。

- 管理画面の当日予約タブに予約が増えていること。
- `kkpay_reservations.reservation_type = same_day` の行が作成されていること。
- `kkpay_reservation_events` に `reservation_created` / `reservation_cancelled` が記録されていること。
- お客様から「時間枠が選べない」「確認できない」「キャンセルできない」という問い合わせがないこと。
- Stripe 決済を伴うプレミアム予約の残席計算に異常がないこと。

管理画面では、KichiKichi Paid Reservation の当日予約タブで当日の日付を選び、予約行とキャンセル済み行を確認する。DBで確認する場合は、WordPress の実テーブル接頭辞に置き換えて次を実行する。

```sql
SELECT id, reservation_date, time_slot, seating_preference, status, created_at
FROM wp_kkpay_reservations
WHERE reservation_type = 'same_day'
ORDER BY id DESC
LIMIT 20;

SELECT reservation_id, event_type, actor_type, created_at
FROM wp_kkpay_reservation_events
WHERE event_type IN ('reservation_created', 'reservation_cancelled')
ORDER BY id DESC
LIMIT 20;
```

## PR 9 で行わないこと

- 旧当日予約プラグインの停止。
- 旧当日予約テーブルの削除。
- 旧当日予約データの移行。
- `kkpay_accepted_dates` の削除。
- 本番ページの実際のショートコード差し替え。
- Feature Flag の追加。PR 9 では手順書による段階切り替えと切り戻しで制御する。
